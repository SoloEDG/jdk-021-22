# 午市厨房

需要 Node.js 22 或更新版本。

```sh
npm install
npm run dev
```

类型检查及生产构建：

```sh
npm run typecheck
npm run build
```

无头诊断测试（不依赖浏览器，用 esbuild 打包纯模型后在 Node 中验证重演与归因）：

```sh
npm run test:headless
```

## 营业诊断

打烊结算在原有评级、净收益、单数之外，新增一份可解释瓶颈的营业诊断报告：

- **逐单时间构成**：把每单划分为待接单、缺料/备料等待、等锅、烹饪、等上菜五段，
  同一时刻每单只归入一段，重叠等待不重复相加。
- **阻塞判定**：按“单因子解除后能否推进下一步”判定；必须同时解除多个因子才能
  推进的标记为联合阻塞（如缺料且灶台全忙）。
- **损失定位**：超时赔付、丢弃、火候折损、失温折损、采购支出逐笔映射回当时场景。
- **改进重演**：每条建议都用原局客流与原玩家动作时刻重演，仅改变资源；因资源
  变化而失效的动作明确跳过并说明，并列出对其他订单的挤占损失，逐单差额与总账配平。
- **重新调度潜力**：不改资源、只换排程的启发式测算，独立成区，不混入任何单项改进收益。
- **局间可比性**：仅当菜谱（含价格）签名与来客表完全一致时才做归因对比；客流或
  菜谱不同会明确提示“不可直接归因”。
- **隔离性**：历史局归档写入独立存储键，诊断为纯函数计算；分析旧局不会修改新一局
  或历史最佳。暂停冻结营业钟、不计耗时，打烊同刻的交付与账本口径一致。
